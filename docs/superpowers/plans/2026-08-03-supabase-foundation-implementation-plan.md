# Supabase Foundation Implementation Plan

> **Execution rule:** Use this plan one Task at a time. Finish the Task's minimum verification, commit it independently, then stop for human review before starting the next Task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional, non-blocking Supabase account foundation to Toss: reproducible local infrastructure, secure account tables, native Sign in with Apple, session restoration, profile/preference sync, account settings, logout, and in-app deletion, while preserving the existing offline Toss experience.

**Architecture:** `TossApp` constructs an `AppDependencies` graph and renders the existing coin experience immediately. Account state runs independently through protocol-backed services and repositories. PostgreSQL owns account records and RLS, Supabase Auth owns Apple identities, and a JWT-protected Edge Function is the only privileged account-deletion path.

**Tech Stack:** iOS 17.5, SwiftUI, MVVM, AuthenticationServices, Supabase Swift 2.x through Swift Package Manager, Supabase CLI, PostgreSQL, pgTAP, Supabase Edge Functions/Deno, XCTest.

## Global Constraints and Stable Interfaces

- Keep `IPHONEOS_DEPLOYMENT_TARGET = 17.5`.
- Do not alter `ContentView`, RealityKit/USDZ loading, gesture/motion/result state, Haptic timing, or WAV behavior except the narrow preference enable/disable hooks in Task 6.
- `AppRootView` renders `ContentView()` immediately. Session restoration and sync run in an independent `Task`; Toss never awaits network work.
- Guests are local-only users, not Supabase anonymous Auth users. Default coin use never creates an account.
- Client configuration contains only `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY`, injected per build configuration.
- Supabase secret/service-role keys, Apple `.p8`, Apple client secrets, database passwords, access tokens, and refresh tokens never enter the app, Git, logs, fixtures, or example values.
- Supabase Auth `identities` owns Apple subjects. No business table stores `apple_subject`.
- Each executable task starts with a failing focused test, ends with scoped verification, and has one English commit.
- Execute exactly one Task per implementation session. After its minimum verification and independent commit, stop for human inspection.
- Do not repeat the full build or the original 39-test suite for every small step. Run them only after package/project dependency changes, at major integration gates explicitly listed below, and in Task 9.
- The verified simulator destination is `platform=iOS Simulator,name=iPhone 15 Pro,OS=17.5`. If unavailable, run `xcrun simctl list devices available`, report compatible iOS 17.5 devices, and do not alter the deployment target.

```swift
struct SupabaseConfiguration: Equatable {
    let url: URL
    let publishableKey: String
    static func load(from bundle: Bundle) throws -> Self
}

enum AccountSession: Equatable {
    case guest
    case restoring
    case authenticated(userID: UUID)
}

enum ServerSessionRevocation: Equatable {
    case revoked
    case deferred
}

struct AppleSignInCredential: Equatable {
    let identityToken: String
    let authorizationCode: String
    let rawNonce: String
    let displayName: String?
}

@MainActor
protocol AppleSignInServicing {
    func signIn() async throws -> AppleSignInCredential
}

protocol AccountAuthServicing {
    func restoredSession() async throws -> AccountSession
    func signInWithApple(identityToken: String, rawNonce: String) async throws -> AccountSession
    func signOut() async throws -> ServerSessionRevocation
}

protocol UserProfileRepository {
    func fetch(userID: UUID) async throws -> UserProfile
    func updateDisplayName(_ displayName: String?, userID: UUID) async throws -> UserProfile
}

protocol UserPreferencesRepository {
    func fetch(userID: UUID) async throws -> UserPreferences
    func update(_ preferences: UserPreferences) async throws -> UserPreferences
    func bootstrap(userID: UUID, guestPreferences: LocalPreferences) async throws -> PreferenceBootstrapResult
}

enum PreferenceBootstrapResult: Equatable {
    case uploadedGuestPreferences(UserPreferences)
    case existingAccount(UserPreferences)
}

struct LocalPreferences: Equatable {
    let soundEnabled: Bool
    let hapticEnabled: Bool
}

protocol AccountDeletionServicing {
    func deleteAccount(authorizationCode: String, requestID: UUID) async throws -> AccountDeletionResult
}

struct AccountDeletionResult: Equatable {
    let deleted: Bool
    let appleRevocation: AppleRevocationStatus
}

enum AppleRevocationStatus: String, Equatable {
    case revoked
    case alreadyInvalid = "already_invalid"
    case manualRequired = "manual_required"
}
```

`AccountStore` is the single `@MainActor ObservableObject` for session/profile/preferences. `AccountViewModel` owns presentation, confirmation, loading, and user-facing errors. Views never call Supabase directly.

## Task 8: Implement Secure In-App Account Deletion

**Create:** deletion-request migration/test, function env example, shared TypeScript files, Edge Function/test, iOS deletion protocol/service/view, dedicated iOS tests.

**Modify:** account view model/settings, DI, UI test, and `config.toml` only to keep delete function JWT verification enabled.

**Inputs/outputs:** Client first completes native Apple reauthentication and refreshes its Supabase session, then sends `{ authorizationCode, requestID }`. Success is HTTP 200 with `{ deleted: true, requestID, appleRevocation: "revoked" | "already_invalid" | "manual_required" }`. Stable failures are limited to 401 invalid/stale Supabase reauthentication, 422 identity mismatch, and 500 Toss/Supabase data deletion failure. Apple revocation failure is not a data-deletion failure.

`account_deletion_requests` has exactly `request_id uuid primary key`, checked `status text`, `requested_at timestamptz`, nullable `completed_at timestamptz`, and checked `apple_revocation_status text`. It stores no user UUID, Apple subject, token/code, email, name, IP, log body, or sensitive error.

**Prerequisites:** Task 7; Apple server credentials configured only in local/hosted function secret stores.

**Failing tests**

- [ ] pgTAP: exact columns, status checks/transitions, forced RLS, no client privileges, server-only access, primary-key idempotency, and completed timestamp rules.
- [ ] Deno: invalid/stale JWT, malformed body, same-ID replay in each state, identity mismatch, Apple code already invalid, Apple exchange/revocation outage, Auth deletion failure, successful deletion, and sanitized logs.
- [ ] XCTest: fresh Apple reauth required, cancellation harmless, stable request ID retry, success returns guest.
- [ ] XCTest: `manual_required` still clears the deleted Toss account and presents the Apple ID Settings guidance.
- [ ] UI: discoverable destructive action, explicit confirmation, reauth, and cancellation preservation.
