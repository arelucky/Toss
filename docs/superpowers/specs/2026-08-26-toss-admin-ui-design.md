# Toss 管理后台 UI 设计说明

**日期：** 2026-08-26  
**状态：** 设计已确认，等待 UI 实施  
**范围：** 管理后台的 `/coins` 与 `/coins/:id`；不改变现有 Supabase、Edge Function 或 iOS 合约。

## 目标与边界

本设计让单管理员能快速判断每枚免费硬币的发布状态、当前生效版本、资源准备情况、排序与精选设置，并能在不离开当前上下文的情况下完成现有的创建、上传、发布、回滚、隐藏与恢复操作。

视觉延续 Toss 的深色、暖象牙白与香槟金语言，但后台以信息密度和可扫描性优先：金色只用于主操作、选中与必要强调，状态不使用彩虹色。页面仅消费既有 `admin-coins` actions：`listDrafts`、`createCoin`、`updateCoin`、`createVersion`、`createUploadURL`、`publishVersion`、`rollbackVersion`、`hideCoin` 与 `restoreCoin`。

不新增价格、StoreKit、Premium、付费权限、订阅、购物车、用户统计、多管理员、审计、Storage 浏览器或手工路径编辑。

## 现有数据契约与呈现原则

| 数据 | 现有来源 | UI 使用方式 |
| --- | --- | --- |
| 硬币 | `listDrafts` 的 `coins` 映射 | `id`、`slug`、`displayName`、`description`、`sortOrder`、`isFeatured`、`status`、`activeVersionID`、`publishedAt` |
| 版本 | 每枚硬币的 `versions` | `id`、`versionNumber`、`status`、`modelPath`、`previewPath`、`modelByteSize`、`modelSHA256`、`minAppVersion`、`assetSchemaVersion`、`publishedAt` |
| 资产 | 固定路径 | 模型位于 `coin-models-free/<modelPath>`，预览位于 `coin-previews/<previewPath>`；路径由服务端生成，只读展示 |
| 状态 | 既有数据库与 Function | 硬币：`draft`、`published`、`hidden`；版本：`draft`、`published` |

`coins.updated_at` 存在于数据库，但当前 `admin-coins` 管理列表响应不返回该字段。因此本次 UI 不显示伪造的“Updated At”；若后续既有响应开始提供 `updatedAt`，列表可在既定列位显示本地化日期，否则该列不渲染。

同理，当前列表响应没有逐对象的 Storage `objectExists` 结果。资产状态必须诚实表达：已发布 active 版本可标记为 **Ready**（发布 RPC 已验证两个对象）；草稿版本只能标记为 **Incomplete / Awaiting upload**，不可声称对象已存在。**Missing model** 与 **Missing preview** 是为将来已有真实检查结果时预留的语义，不得在没有数据依据时猜测显示。

## 视觉原则

- **底色与层次：** 近黑炭黑工作区，略亮的深灰表面承载表格、表单与操作区；分隔线低对比但可辨认。
- **文字：** 暖象牙白为主文字，低透明度象牙白为辅助信息。slug、路径、SHA 使用等宽字体，但不使用纯白大段代码块。
- **强调：** 香槟金用于 Create Coin、可执行 Publish、已选中筛选和细边框；禁用态降饱和且仍满足对比要求。
- **密度：** 采用 8pt 间距节奏。桌面表格行高约 52–60pt；点击目标最小 36pt，主要按钮最小 40pt。
- **状态：** 不只依赖颜色；每个 badge 同时有文字与边框/填充差异。隐藏项降低整体对比度，但仍完整可读。

### 状态语义与颜色

| 语义 | 文案 | 视觉处理 |
| --- | --- | --- |
| 草稿 | 草稿 | 中性石墨描边，暖灰文字 |
| 已发布 | 已发布 | 极浅香槟金底或描边，象牙白文字 |
| 已隐藏 | 已隐藏 | 低对比炭灰底、暖灰文字、眼睛划线图标；不使用警告红 |
| Ready | 已就绪 | 金色细勾与“已就绪”，仅用于已验证的 active published 版本 |
| Incomplete | 待上传 | 中性描边与“待上传”，用于草稿或无可验证资源状态 |
| Missing model / preview | 缺少模型 / 缺少预览 | 仅在将来已有真实对象检查结果时使用；低饱和琥珀提示，不使用成功色 |
| 失败 | 无法加载 / 操作未完成 | 低饱和砖红文本与简短安全提示；不显示 Function、SQL、路径或密钥细节 |

## Coins 列表页：`/coins`

### 桌面结构

页面采用最大宽度工作区，按以下顺序布局：

1. **页面头部**：左侧为 `Toss 管理后台` eyebrow 与 `硬币` 标题；右侧固定主操作 `创建硬币`。
2. **创建区**：主操作展开为紧凑的内联表单，只有 `Slug` 与 `Display Name`，保留当前一次提交后进入编辑页的流程。表单不变成向导。
3. **状态筛选**：`全部`、`草稿`、`已发布`、`已隐藏` 单选 segmented control；筛选在已加载的管理目录上进行，不改变 `listDrafts` action。
4. **管理表格**：高密度、可横向滚动但不压缩字段语义。默认顺序继续使用服务端的 `sort_order`、`slug` 顺序。

表格列如下：

| 列 | 内容与规则 |
| --- | --- |
| Preview | Classic 使用本地预览；动态项仅在已有公开预览路径时显示小型 WebP 预览。加载/失败使用中性占位，不影响其它列。不得请求或展示 signed URL。 |
| Display Name | 主文字；下方可放一句截断的描述，不存在时不留空白行。 |
| Slug | 等宽、单行、省略号截断；可复制为辅助操作但不自动改写。 |
| Status | 草稿 / 已发布 / 已隐藏 badge。隐藏行整行降低对比度，不降低可操作性。 |
| Active Version | `vN`；没有 active version 显示 `—`。点击编辑入口后在版本面板查看详情。 |
| Assets | active published 版本且路径完整时 `已就绪`；草稿或无 active 时 `待上传`。未来若 API 给出真实缺失状态，再显示 `缺少模型` 或 `缺少预览`。 |
| Sort Order | 右对齐整数；不在列表直接编辑，避免隐式保存。 |
| Featured | 明确的 `是` / `否` 或小星标加辅助标签；不能只靠图标。 |
| Updated At | 仅在 API 实际提供 `updatedAt` 时显示；当前不渲染此列。 |
| 操作 | `编辑` 始终可用；已发布显示 `隐藏`，已隐藏显示 `恢复`，草稿不显示两者。 |

`创建硬币`、`隐藏`、`恢复`均复用现有请求与确认语义。隐藏确认明确说明资源保留；恢复确认只说明恢复至已发布。不会在列表引入批量操作、删除或拖放排序。

### 状态、空态与错误态

- **初始加载：** 表格区域显示 5–7 行低对比 skeleton；头部和筛选可见但不可触发重复加载。
- **筛选为空：** 保留列标题，显示“此状态下暂无硬币。”；全部为空时显示“尚无硬币。创建第一枚硬币即可开始。”及 Create Coin 主操作。
- **加载失败：** 在表格上方显示安全错误面板和“重新加载”按钮；保留已经显示的旧列表，避免突然清空上下文。
- **操作进行中：** 仅对应行或按钮显示忙碌态，禁用相同行的重复操作；其它硬币仍可编辑。
- **隐藏项：** 始终出现在“全部”和“已隐藏”筛选中，状态与恢复入口明显但不刺眼。

### 小窗口降级

- 宽度低于约 1100px 时，表格置于明确的横向滚动容器，第一列名称与操作列保持可读。
- 宽度低于约 760px 时，切换为两行密度列表：第一行 Preview、名称、状态；第二行 slug、active version、assets；操作收纳为同一行的文本按钮。仍不引入汉堡菜单或新导航。
- 创建区从三列改为垂直字段加全宽按钮；筛选可横向滚动，不换成下拉菜单。

## Coin Editor：`/coins/:id`

### 页面头部

顶部在一行内提供返回 `硬币`、Display Name、只读 slug、硬币状态 badge 与保存状态。主要操作按现有状态出现：

- 草稿：可保存、创建/上传版本、发布符合条件的最新草稿版本；不显示隐藏或恢复。
- 已发布：可保存、可创建下一个草稿版本、可发布或回滚符合条件版本、可隐藏。
- 已隐藏：保留只读版本历史与基本信息；显示恢复，隐藏按钮不显示。

保存状态仅显示“未保存更改”“正在保存”“已保存”或既有安全错误，不显示内部响应。发布成功继续使用非阻塞 `role="status"` 提示“版本已发布。”；回滚不得复用该成功文案。

### A. Basic Information

双列工作区左栏的首个面板，包含：

- Display Name（必填）
- Description（可选，多行）
- Sort Order（整数）
- Featured（明确开关与文本）

slug 在头部只读显示，不能编辑。保存按钮位于此面板底部，保存、发布或回滚开始时清理旧成功提示。窄屏下字段堆叠为单列。

### B. Current Version

右栏顶部的状态面板，展示：

- Active Version：`vN` 或 `—`
- Version status：草稿 / 已发布
- Published At：仅在版本响应实际提供时显示
- Assets：按“已就绪 / 待上传 / 缺少模型 / 缺少预览”的诚实规则显示
- 可用操作：发布最新 draft、回滚至最高版本号的非活动 published 版本

发布与回滚都继续使用现有二次确认、busy 防重复点击及服务端原子 RPC；页面不能基于数组顺序猜测目标版本。

### C. Assets

版本资产区不编辑路径，按选定或新建版本显示：

- **Preview**：固定预览路径存在且可公开读取时展示 WebP；未有可展示图片时使用明确占位与路径文本，不显示虚假缩略图。
- **Model**：USDZ 文件状态、`modelByteSize` 的可读格式、`modelSHA256` 的等宽截断展示（可复制，但不在日志或错误中输出）。
- **Compatibility**：`minAppVersion` 与 `assetSchemaVersion`。
- **Storage paths**：`coin-models-free/<modelPath>` 与 `coin-previews/<previewPath>` 只读；空值不拼接。
- **上传**：沿用现有 `创建版本并上传` 流程。它创建一个新的不可变 draft version 后对两个固定路径上传，不能覆盖已发布版本。

当前 API 没有“替换同一版本 staging 资产”的能力，因此 UI **不显示 Replace/重新上传现有版本**。上传失败保留所选文件和安全错误提示；不会在 UI 中暴露 signed URL。

### D. Version History

全宽面板，版本号降序排列，每行显示：版本号、状态、是否 active、模型/预览路径摘要、大小、最低 App 版本、发布日期（有数据时）与可执行的既有操作。

- Active published 行带金色细边或 `当前生效` 标签。
- Draft 行显示 `发布`，只在它是服务端允许的最新可发布草稿时可用。
- 非活动 published 行显示 `回滚到此版本`，仅在服务端允许时可用。
- 版本不提供删除、弃用、复制、手工改路径或直接编辑 SHA。
- 隐藏硬币的历史继续可见，便于恢复后的管理，但不显示隐藏操作。

### 布局与降级

- 宽屏（≥1200px）：Basic Information 与 Current Version 双列，Assets 与 Version History 跨全宽。
- 中等宽度：双列保持，版本历史可横向滚动，避免压缩 SHA、路径与操作。
- 小窗口（<760px）：所有面板单列；页面头部换行为返回/状态一行、名称/slug 一行、操作一行；版本行改为信息堆叠，操作不被折叠隐藏。

## 交互、安全与无障碍

- 所有主按钮、行操作与文件选择保持可键盘访问，触控区域至少 36pt，关键操作优先达到 40pt。
- icon 仅作辅助；状态、Featured、资产 readiness 与禁用原因均有文字。
- `aria-live` / `role="status"` 用于成功、上传与非敏感错误反馈；确认弹窗维持既有原生确认行为。
- 无会话、无权限、冲突或服务失败继续沿用现有中文安全提示，绝不显示 JWT、管理员 ID、service-role key、SQL 错误、堆栈、Storage signed URL 或本地文件路径。
- 前端文件类型/大小检查仅改善体验；Function 继续是路径、版本与发布转换的安全边界。

## 不允许在后续 UI Task 新增的内容

- 新的后端 action、数据库字段、migration、Storage policy 或对象路径规则
- 批量发布、批量隐藏、批量排序、拖放排序、删除硬币或删除版本
- 版本覆盖上传、版本克隆、路径编辑、SHA 编辑或签名 URL 展示
- 价格、产品 ID、购买、订阅、Premium、权益、购物车、交易或 StoreKit
- 用户管理、角色管理、多管理员、审计搜索、图表、营销 Dashboard

## 验收标准

1. `/coins` 在一屏内可扫描名称、slug、状态、active version、资产语义、排序和精选；创建与编辑入口无需跳转到不存在的新页面。
2. 全部 / 草稿 / 已发布 / 已隐藏筛选正确，隐藏硬币仍可见且只显示恢复操作。
3. 所有资产文案只表达接口已知事实；没有对象验证数据时不伪造 Ready 或 Missing 状态。
4. `/coins/:id` 让管理员清楚区分基本信息、当前生效版本、资产与版本历史；固定 Storage 路径只读。
5. 发布、回滚、隐藏、恢复、上传、确认、busy、权限与安全错误的现有业务语义保持不变。
6. 宽屏高密度可读；小窗口不遮挡表格操作、版本行、上传状态或底部内容。
7. 页面没有价格、付费、用户统计、虚假同步状态或任何本说明明确禁止的能力。
